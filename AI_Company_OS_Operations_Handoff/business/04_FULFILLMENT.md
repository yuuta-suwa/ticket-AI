# 提供工程と原価記録
本書と ../IMPROVED_WORKFLOW.md を使用します。以下は運用設計で、実顧客への提供を完了した記録ではありません。

| 工程 | 実施 | 確認・出力 |
|---|---|---|
| 発注範囲 | 本人と顧客 | 1職種・1テーマ、金額、具体的納期、検収・修正条件 |
| 入金 | 本人が証憑照合 | 全額受領、取引参照。決済成功と口座着金は別管理 |
| 素材 | AIが不足整理、本人が権利確認 | 現行素材と内容確認担当 |
| 制作許可 | 本人 | 対象scope、素材、明示的な期限。変更・失効後は流用しない |
| 構成と原稿 | 制作機能 | 元資料の根拠、3ロープレ、評価表、講師進行案 |
| 品質確認 | AIが照合補助、本人が最終確認 | 事実・仮定・架空例、編集原稿とPDFの整合 |
| 顧客確認 | 顧客担当 | 商品情報と現場表現、範囲内修正をまとめて1回 |
| 最終納品 | 当初は本人 | 確認済み最終版と送付根拠 |
| 実使用 | 顧客と本人 | 使用日、使った部分、負担の変化、使いにくかった点 |
| 原価・知識 | 採算管理と本人 | 全作業と費用、修正原因、再利用してよい教訓 |

## 時間の考え方

旧「営業・制作の合計5時間」は実測のない仮定なので、標準工数として扱いません。
比較用の改善モデルでは、制作・ヒアリング・検品・修正・説明等5時間と、未受注を含む配賦営業8時間を置きます。これも仮定です。
制作5時間は目標保証ではありません。各工程で計時し、最終の使用確認・問い合わせ対応も足します。
営業は失注を含むキャンペーン全体の時間を記録し、別の有料顧客の数で配賦します。

7営業日は入金・素材・範囲が揃ってからの初稿目安です。使用日と最終確認の日程を見て、発注時に具体的な納期を合意します。
素材不足や顧客確認の遅れがあれば、黙って納期をずらさず、影響と新日程を確認します。

## 取引と例外

初期は前払の有料制作案です。提供範囲・条件・支払方法は事業者本人と顧客が確定します。
支払事業者や請求方法の条件は設定時に一次情報で確認します。
範囲変更は再見積し、元の価格や許可のまま着手しません。
返金は実際の金融記録と原因対策を両方残し、顧客が使用したことや満足したことに置き換えません。
