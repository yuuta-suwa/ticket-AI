# 権限・予算・停止
## 自動運転の範囲
日常の仕事は登録済みの職務と権限内で実行する。例外だけをオーナーへ具体案付きで報告する。
初期版に外部公開・送信・支出の道具はない。契約締結や資本移動も対象外。

## 実装した制御
社員IDを道具に固定。直属の部下への発行。担当外の取得禁止。自己検収禁止。
親計画の受入、同一プロジェクトの依存、前工程の受入を検査。
1プロジェクト最大64タスク。階層の深さはAI社長0、部長1、課長2、担当3。試行は初回＋再試行2回まで。
架空の全社1000単位を共通台帳で予約・消費。複数DB接続でもトランザクションで予約を直列化。
同じ発行キーと内容の再処理は同じ仕事を返す。同じキーで内容が変わった場合は拒否。
期限切れのタスクは回収して予約分を解除。外部副作用がないため、この試作では安全に再実行できる。

## 未実装の本番制御
全社・事業・部門ごとの実費、媒体別権限、アカウント別権限、モデルの共通費用予約、API結果照合、入金照合、分散排他、クレーム率による停止。
本番接続はこれらの必要部分を追加し、当該経路で試験してから有効化する。

## モデル利用
npm run devはCOMPANY_LLM_ENABLED=1がないと起動しない。モデル認証は本人がローカルで設定する。
モデルごとの利用料は契約と経路による。simulation_unitsは実際の請求額ではない。
eveのsessionUsageは各セッションの次の呼出しを制限する。上限に到達した呼出しの費用は既に発生し得る。
複数社員の総額上限やインフラ費まで制御したとは説明しない。
実費制御を検証するまでは大規模な並列起動や24時間運転を行わない。

## 全社停止
CEO、監査役、本人のCLI操作で台帳の処理を止める。
本人のCLIだけが再開できる。再開前に未確定の処理と障害原因を確認する。
停止は既に進んでいるモデル推論の取消や情報の回収を保証しない。

## セキュリティ境界
試作は信頼された単一オーナーのローカル端末用。
任意のshell、ファイル操作、Web検索、外部接続をAI社員に与えない。eveの標準道具を無効化し、必要な業務道具だけ定義する。
開発時の既定拡張も起動スクリプトで無効化する。モデルから会社規程やソースを変更する道具は与えない。
本人が直接ソースやDBを書き換える権限までは阻止しない。ネット公開用の認証・テナント分離は未実装。
