# 次の実装担当への指示
このプロジェクトはAI会社・部署・社員の基盤試作です。FRIDAYなど他のシステムへの統合は前提にしません。

## 最初に行うこと
README、MASTER_SPEC、07_IMPLEMENTATION、package-lock、テストを確認。
npm ci --ignore-scripts、npm test、npm run typecheck、eve info --jsonで再現。
導入したnode_modules/eve/docs/README.mdと必要なガイドを読み、同梱バージョンのAPIを使う。

## 変えない設計
AI社長1、部長8、課長16、担当16、監査役1。社員の職務とモデルを分離。
業務ID、検収理由、成果物版、出典、依存関係を保持。
道具の実行IDを固定し、モデル入力から自由な社員IDとして権限を使わせない。
AI社長・部長・課長・担当の発行階層と自己検収禁止を維持。
予算、外部権限、停止条件をAIの指示文だけに依存させない。

## 次に完成させる機能
- 台帳の仕事発行とeve社員呼出しを、重複防止と再開が可能な単一の実行フローへ統合。
- 会話の必要部分を業務ID付きで取り込み、原文・要約・教訓を分離。
- モデルの全社費用管理。各セッションのsoft limitを全社の請求上限と説明しない。
- 社員の休止、担当変更、職務版、評価例比較、手順更新を実装。
- 顧客データに先立ち、分類とアクセス制御をタイトル・検収理由・メッセージまで拡張。
- 外部操作を接続する場合だけ、該当サービスの認証・権限・利用条件を確認。
- 一事業の実際の成果を測定し、模擬と下書きと実績を分離。

## 進め方
通常の可逆な実装と検証は自律的に進める。本人の認証、実費、契約、公開対象など未設定の部分は具体案と未接続表示を用意する。
秘密鍵の全文をチャットに要求しない。モデル呼出しの認証がなければ、模擬経路で先に作業を進める。
未接続の機能や実行していない試験を完了と報告しない。

## 本番の受入
一つの目的が部長→課長→担当へ渡り、納品・検収・他部門への引継ぎ・実費・実成果まで追跡される。
停止と再開、重複処理、依存待ち、自己承認、越権、費用超過、会話削除と派生物削除を検証。
収益性は実際の顧客・販売・費用で別途判定する。
