## 2. 変更一覧
- `src/`：2アプリ共通のソースを新しく作りました（`index.html` / `app.js` / `sw.js` / `icon.svg`）。
  - ログイン、メール認証、ロール判定、Supabase の読み込み、サーバー保存、管理画面、システムAIの呼び出しをすべて取り除きました。
  - 端末内保存の仕組みを1か所にまとめました（`life-stage2:<variant>:v1`、UIの状態は `…:ui`）。
  - 保存中／保存済み／保存できない、の3つの表示を区別します。保存に失敗しても、入力はメモリに残ります。
  - 壊れた保存データは削除せず、`…:broken:<時刻>` に退避します。
  - バックアップの書き出しと復元を追加しました。
    - ファイルに含める項目：`schemaVersion`、`appVariant`、`exportedAt`、`workIds`
    - 復元前に、形式・版・サイズ（5MBまで）を検査します。さらに中身のプレビューと現在の記録への影響を表示し、確認してから置き換えます。
    - A から B へ復元する場合、コアの記録は除外し、そのことを画面に表示します。
    - B から A へ復元する場合、置き換わるのは共通部分だけで、A のコアの記録は残ります。
    - 旧ログイン版の書き出しファイル（`v:2`）も読み込めます。
  - 設定に「このアプリの記録だけを削除」（確認あり）を追加しました。初回表示と設定に、端末保存についての説明文を入れました。
  - 旧版のメールリンクの認証パラメータ（`?code=` や `#access_token` など）は処理せず、URLから取り除きます。
  - CSP で通信先を自分の origin（`connect-src 'self'`）に限定しました。
- `build.mjs`：A と B を出力します。B ではコアのブロックを削除し、コア教材の目印（`CORE_MARKERS`）が1つでも残っていたらビルドを失敗にします。アプリの種類はビルド時に固定されます。
- `src/sw.js`：アプリごとにキャッシュ名を分けました。他のアプリのキャッシュは削除せず、配下にある別アプリのパス（`members/` `legacy/` `preview/`）にも介入しません。
- `legacy/`：変更前の本番ファイルをそのまま保管しています（ロールバック用・移行用）。`legacy/sw.js` は `/legacy/` に配置しても他アプリのキャッシュを消さないよう、キャッシュ名と削除範囲だけ直しました。
- `tests/variants.test.mjs`：受入テストを追加しました。`docs/current-state.md`：変更前の調査を追加しました。

## 5. 旧データ・端末保存
- **旧DB（Supabase）はそのままです。** テーブル、ユーザー、RLS、Edge Function のどれも変更・削除していません。新しいアプリは Supabase に接続せず、キーも含んでいません。
- 旧ユーザーの記録は**自動では引き継ぎません**。移行の手順は次のとおりです。
  1. 旧ログイン版（現在の本番。切替後は `/legacy/`）にログインする
  2. マイページの「記録を書き出し（JSON）」でファイルを保存する
  3. 新しいアプリの「設定 → バックアップから復元」でそのファイルを選ぶ
- 旧版がブラウザに残したデータ（`ls2.ui`、`ls2.cache.<uid>`、`sb-…-auth-token`、`ls2.local`、`lifestage2.v1`）は、新しいアプリでは**読まず、表示せず、削除もしません**。保存キーが別なので、自動で表示されることはありません。
- 端末保存の制約：
  - 別の端末とは同期しません。
  - ブラウザのデータを消すと記録も消えます。
  - 同じ端末・同じブラウザを使う人とは記録が共有されます。
  - A と B は同じ origin（`yuuta-suwa.github.io`）にあるため、記録はキー名で分けているだけです。開発者ツールを使えば、同じ端末の中で両方のキーが見えます（他の端末には見えません）。
- バックアップ：設定から「バックアップを書き出す」でJSONを保存し、「バックアップから復元」で読み込みます。

## 6. 要判断（本番切替の前に決めること）
1. **origin を分けるか**：仕様 §4 では2つの独立した origin を推奨しています。GitHub Pages では同じアカウントのページがすべて `yuuta-suwa.github.io` になるため、今回はパス（`/` と `/members/`）とキー名で分けています。origin も完全に分けたい場合は、B 用に別の配信先（Cloudflare Pages / Netlify / Vercel など、アカウント作成が必要）を用意してください。`dist/members/` をそのまま置けば動きます。
2. **旧版をどれくらい残すか**：`/legacy/` に旧ログイン版を残すのは、移行のための書き出し用です。残す期間と、案内の方法を決めてください。
3. **旧版でメールリンクを使うか**：`/legacy/` でメールリンクのログインを使う場合は、Supabase の Redirect URLs に `https://yuuta-suwa.github.io/ticket-AI/legacy/` を追加してください。パスワードでのログインなら追加しなくても使えます。
4. **配布の方針**：A は URL を知っている人なら誰でもコア向けワークを使えます。限定公開はできないので、A と B の URL をそれぞれ誰に渡すかを決めてください。

```

# 2) gh-pages を作業用フォルダに取り出す
```

直下の旧 Service Worker（`ls2-v4`）は、A の `sw.js` が同じURLで置き換え、旧版の画面キャッシュだけを消します。端末内の記録は消えません。

## 8. ロールバック
```

# または legacy/ の中身を直下へ戻して push
```
