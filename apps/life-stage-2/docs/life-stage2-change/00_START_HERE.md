# Claude Codeへの渡し方

今回の成果物は変更指示書です。アプリそのものの改修・公開はまだ行っていません。

## 手順1：既存アプリのソースを用意
既にClaude Codeで開発している場合は、そのLIFE STAGE 2.0のプロジェクトを開きます。空のフォルダから始めないでください。
ソースがZIPなら解凍したアプリのフォルダを開きます。仕様書だけでは既存機能を維持した改修はできません。
本番URLや開発画面のURLだけで、ソースへアクセスできるとは限りません。

## 手順2：指示書を置く
このフォルダを既存プロジェクトの docs/life-stage2-change/ に置きます。ファイル名はそのままにします。
既存のAGENTS.md、CLAUDE.md、ソースを上書きしないでください。

## 手順3：実装を依頼
Claude Codeをそのプロジェクトで開き、次を貼り付けます。

```
docs/life-stage2-change/01_CHANGE_SPEC.md と
docs/life-stage2-change/02_CLAUDE_CODE_PROMPT.txt を読んでください。
今回の依頼として、02の指示に従って既存アプリを改修し、全メンバー専用アプリを1個追加してください。
まず現物の実装状況を確認し、その後は実装・テスト・プレビュー確認まで進めてください。
```

ファイルを置けない場合は01の全文と02の全文を同じ会話に貼り付けます。
パスワード、秘密鍵、本番DBの内容をプロンプトに貼り付ける必要はありません。

## 手順4：最初の調査結果を見る
「既存コアの実装有無」「ログイン依存機能」「旧記録の移行方法」「2アプリの作り方」を確認します。
未実装のコアがある場合、今回の認証変更だけで教材まで完成するわけではありません。
共同ルームなどが実運用中なら、代替方式による機能差分を確認してから本番を切り替えます。

## 手順5：実物を確認
1. Aを新しいブラウザで開き、ログイン不要で全メンバーとコアの実装済み機能を利用できるか。
2. Bを開き、コアの表示がなく、ワークが利用できるか。
3. A/Bに異なる回答を入れて再読み込みし、記録が混ざらず残るか。
4. バックアップと復元を試せるか。
5. 別ブラウザで、自分や他人の記録が勝手に出ないか。

## 手順6：公開を引き継ぐ
Vercel等の既存の公開設定を実物で確認してもらい、A/Bを別の公開先に配備します。
接続権限がない場合、Claude Codeから具体的な設定手順を受け取って実施します。
公開先のURLは実際に発行されたものを使い、仮URLを完成URLとして配布しないでください。

## 今回の注意点
- ログインがないAは、URLを知る人ならコアも利用可能です。
- 端末内保存は端末間で自動同期されません。共有端末では同じ記録が見えます。
- 旧ユーザーの記録は無認証で自動引き継ぎしません。
- 教材の充実とプレゼン制作は、今回の2アプリ化から分けて次の作業にします。
