# 実装順と合格条件

## 実装の段階
| 段階 | 実装すること | 完了の証拠 |
|---|---|---|
| 0 基線 | ソース、依存、認証/DB境界、テスト確認 | 起動方法・元のテスト結果・移植判断 |
| 1 デザイン基盤 | 選択画像/標準方向、トークン、共通UI、レスポンシブ | 3幅の主要画面、長文/空/エラー状態 |
| 2 初回理解 | 目標/期間/強み/制約の段階入力と保存 | 戻る/再開/再読込、旧データとの互換性 |
| 3 相談 | セッション/ターン、構造化レポート、根拠ノート | 入力→生成/取り込み→検証→保存 |
| 4 意思決定 | 施策比較、最優先1件、下書きへの引継ぎ | 重複しない実験ID、出典、上限、期限 |
| 5 検証 | 実績更新、提案の陳腐化判定、再分析 | 入力版と結果履歴、変更/継続の理由 |
| 6 仕上げ | アクセシビリティ、耐障害性、既存機能回帰 | 自動試験、ブラウザー操作、スクリーンショット |
| 7 本番準備 | 認証/DB/秘密/接続の移設、非公開公開手順 | 具体的な差分、設定項目、ロールバック計画 |

7までの調査・準備を行うが、資格情報がない実サービスへ接続したふりはしない。動画生成や大規模CRMなどを先に増やして、相談体験の完成を遅らせない。

## ブラウザーの受入試験
| ID | 操作/状態 | 合格条件 |
|---|---|---|
| UX-01 | 初回で開く | 何を入力し、何が分かるかが伝わる。架空の成果を表示しない |
| UX-02 | 段階入力 | 前後移動・中断・再開が可能。既存プロフィールを失わない |
| UX-03 | 相談テーマを選ぶ | 選んだ目的/文脈が相談へ引き継がれる |
| UX-04 | AI未接続 | APIボタンは実行不可。ルール診断とコピー/取り込みは区別する |
| UX-05 | 根拠を見る | 出典・期間・取得状態へ到達できる。存在しないIDは表示しない |
| UX-06 | 提案を採用 | 同じ操作の二重送信で施策が重複しない |
| UX-07 | 施策を作る | 仮説、変えること、指標、期間、上限、停止条件を保持 |
| UX-08 | 投稿承認 | 全文/素材を確認し、変更時に旧承認が無効化 |
| UX-09 | 結果を更新 | 最新実績と古い提案の違いを認識できる |
| UX-10 | 停止中 | 有料分析・新規実験開始・公開を止め、状態と再開方法を示す |
| UX-11 | 保存競合 | 片方の変更を無言で上書きしない。バックアップ/再読込を案内 |
| UX-12 | 長文・エラー | 読める幅、折返し、再試行、入力保持 |
| UX-13 | 390/768/1440px | 主導線と承認が完結し、横スクロールやCTA重なりがない |
| UX-14 | キーボード | 順序、フォーカス、モーダル閉じ、復帰が機能 |
| UX-15 | 読み上げ/色 | 状態を色だけに依存せず、文字とアクセシブル名を持つ |

## AIとデータの受入試験
- 事実と仮説が別の構造・表示になる。
- 単発の利益を再現性の証明にしない。
- 未取得の指標はnullのまま、実測0は0のまま。
- 対象期間、分母が違う割合を比較しない。投稿間リーチを単純合計してユニーク人数にしない。
- 協賛/ギフト/成果/利用料/販売で、成立条件と報酬の承認を区別する。
- API応答の不正JSON、途中切れ、提供元障害でも結果を成功扱いにしない。
- 不正参照、文中命令、偽のURL、未確認のプログラムからの確定収益の創作を拒否する。
- 自動分析は重複を防ぎ、日次制限・停止を適用。保存と分析失敗を分離する。
- 費用と工数を含む既存24,300円の固定ケースが変わらない。
- 旧JSONバックアップを読み、既存の明細と公開履歴を失わない。

## デザインの判定
最も重要な結論と次の行動が明確か。根拠が近く、自分の情報から作られたと理解できるか。見出しと本文が読め、余白と整列が一貫しているか。相談と戦略ノートが互いを補うか。美しさだけでなく、操作と状態の正確さで判定する。

モック画像への近さだけで完成にしない。コードで構築された画面と基準画像を同じ状態・幅で比較し、差分を修正する。重大な未解決事項があれば完了扱いにしない。

## Claudeの最終提出
動かし方、主要画面、変更ファイル、検証結果、API接続状態、未実装、公開先の差分、必要な本人設定をまとめる。ローカル実装・本物のAI実行・本物の投稿・公開の成功を別々に報告する。
