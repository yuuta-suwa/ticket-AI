# Gate-0 検証記録

## ローカル検証（2026-11-06）
| 項目 | 方法 | 結果 |
|---|---|---|
| 型検査 | `tsc --noEmit` | PASS |
| ユニットテストとHTTPテスト（16件） | `npm test` | 16/16 PASS |
| workerd + ローカルD1/R2 でのE2E（11項目） | `npm run dev` + `npm run smoke` | 11/11 PASS |
| スマホ表示（iPhone 13 相当） | Playwrightで撮影 | 横スクロールなし・コンソールエラーなし |

テストで確認した内容：
- 未サインイン時は401
- 初回サインインは承認待ち。承認前・否認後は利用できない
- 一般会員は承認APIを使えない
- 目標を保存し、再サインイン後に復元。上書き更新もできる
- 他会員の目標と画像は見えず、上書きもできない（`ownerId` を送っても無視される）
- R2への画像の保存・取得・削除
- 画像の形式偽装、SVG、1MB超は拒否
- 別オリジンからの変更、JSON以外の送信は拒否
- 本番構成では開発用Cookieを受け付けない
- 内部エラーの詳細は返さない

## Sites実機で確認が必要な事項（未検証）
1. **取り込み可否**：ChatGPTに「Deploy this project with sites. Check whether it is compatible…」と依頼し、このWorkerの構成（`export default { fetch }`）がそのまま受け入れられるか。変換が必要なら `src/adapters/sites/worker.ts` だけで吸収する
2. **ヘッダー偽装対策**：利用者が `oai-authenticated-user-email` を自分で付けて送った場合に、Sitesがそれを除去または上書きするか（安全性の要。curlで偽ヘッダーを付けて確認する）
3. **サインイン導線**：`/signin-with-chatgpt` を押すとChatGPTのサインインに進み、サイトに戻ってくるか。サインアウトも同様に動くか
4. **日本語の氏名**：`oai-authenticated-user-full-name` の符号化方式。百分率エンコード、UTF-8、そのままのどれで届いても読めるように実装済みなので、実際の表示を確認する
5. **D1マイグレーション**：`migrations/0001_gate0.sql` がSitesで自動適用されるか（形式の扱いは公式に記載がない）
6. **R2**：接続名 `BUCKET` で接続されるか。画像のアップロードと表示ができるか
7. **公開範囲**：「招待した人のみ」にして、別のアカウントでアクセスを確認する。招待された人であれば、アプリ側の承認がなくても承認待ち画面まで進めることを確認する
8. **設定値**：`ADMIN_EMAILS` をSitesの設定画面で入力できるか
9. **データ保存地域**：D1/R2のデータ保存地域は help.openai.com の記事で確認が必要（このセッションからは読めなかった）。会員の非公開情報を保存する前に判断する
10. **料金**：2027年1月1日から計測が始まる。データベースを持つサイトは月25クレジット程度＋使用量

## 設計判断
- 会員の識別子は、Sitesが届けるメールアドレス（小文字に正規化）。内部IDはUUID
- D1には行単位のアクセス制御（RLS）がないため、リポジトリの全メソッドに `ownerId` を必須にし、他人のデータを取得する経路そのものを作らない
- R2 → D1 の順に保存し、D1への書き込みに失敗した場合はR2から削除する。削除は R2 → D1 の順
- AIはGate-0では使わない（主要機能はAIなしで動かす）
